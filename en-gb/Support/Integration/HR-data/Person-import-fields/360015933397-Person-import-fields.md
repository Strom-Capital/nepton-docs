# Person import fields

In the person imports the fields in use are dependent on the source system of the person information imported and the import format used. The fixed fields supported by the [person import](<https://support.nepton.com/hc/en-gb/articles/360003762577>) are listed in the table below. In addition to the generic person import some of the source system dependant import formats support these fields but that is separately mentioned in the source system dependent guidance.
The field names/titles by which the fields are identified are listed in this article. In addition to the English field names you can also use the Finnish titles described in the Finnish version of this guidance. The generic person import also supports customer specific person additional fields. The identifier for these fields for import is the Work contract identifier field. Guidance for setting the field is described [here](<https://support.nepton.com/hc/en-gb/articles/360002430918>).
Emptying the person information field can be ensured using the [**RESET** ](<https://support.nepton.com/hc/en-gb/articles/5080867698717>)keyword in the fields where it is supported. In some fields (in particular, in cases where there can be multiple values imported within a single field) the [RESET](<https://support.nepton.com/hc/en-gb/articles/5080867698717>) keyword has a different behaviour, which is described in the description and/or the [Person import](<https://support.nepton.com/hc/en-gb/articles/360003762577>) page.
On "Default"-person import type, employment dates will be imported exactly as the values are in the import data. In case you need to import using rules and possibilities of "Default"-import, but you want the import to only make the employment date range longer, use the import type "Extend working contract dates".
## Mandatory Fields
### For insert
  * First name
  * Last name


### For update
  * Nepton Id, External identifier 1, Username or Employee number (for identifying the person, match is checked in that exact order)
    * When a Nepton Id or External Identifier 1 is present in the data, it is used to identify the person, which allows the username or employee number to be changed.

  * String-field values do not have maximum length restrictions unless specifically stated otherwise.

## Unique Identifier fields
When re-importing users, Nepton identifies existing users by checking the following fields in exact order: **1\. Nepton Id** → **2\. External identifier 1** → **3\. Username** → **4\. Employee number**. Note that in addition to these primary identifiers, **RFID tag identifiers** and **Pin codes** are also checked for uniqueness (duplicates trigger a warning and are not assigned, though the row is still saved).
### Nepton Id
The Nepton globally unique person identifier (GUID) which is a value automatically generated by Nepton for all persons and displayed on person form. This field can not be reused (even if the user is deleted) and is always unique. Providing a GUID that does not match an existing person when creating a new user will reject the entire row (non-GUID values are stored as-is without deduplication).
### External identifier 1
External Identifier 1 is a unique personal identifier. If user A has External ID 1 “ID-123” and that identifier needs to be assigned to user B, it must first be removed from user A.
### Employee number
Employee number is a unique person identifier. If a **person** **A** has an employee number **1234** and it must be reused for a **person B** , it must first be removed from **person A**. If a row matches an existing user via Employee Number but contains a different User Name, the entire row is rejected.
### Username
User name is a unique person identifier. If a **person A** has a user name **SOMEUSERNAME** and it must be reused for a **person B** , it must first be removed from **person A**. Note that an existing user's username cannot be changed unless "Person identifier" setting / "IdentifierFieldName"-parameter other than username have been defined when importing (the entire row will be skipped).
## Default values
In person import if some fields are not provided, default values are used when adding a new person. In this section fields those can have default values are explained. Also, how to set the default values for these fields are explained.

This is because it is a mandatory field. |  Default values for worktime roles can be set under "Default worktime role (Default used when new person is created)" in section **Employees** > **Administration >** **Settings General**  
Worktime setting group |  When **a new person** is created via the **UI** , or a user import via the UI in **“lenient mode”** , and a setting group is not provided, the new person is set to the default setting group.
