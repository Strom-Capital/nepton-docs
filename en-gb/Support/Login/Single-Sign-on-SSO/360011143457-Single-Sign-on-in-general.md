# Single Sign-on in general

It is possible to enable single sign-on (SSO) in the service. This means that the user's right to log in to the service is verified by an external service. In this case, usernames and passwords are not managed in Nepton. The company's policies regarding the login ID and password are also used in Nepton.
By using a SSO provider, it is possible to enable multi-factor authentication (MFA).
Nepton supports the following service providers:
\- Microsoft login (Microsoft 365, Microsoft Entra ID)
\- Google login
\- SAML2 single sign-on protocol and service providers that use this protocol. For example ADFS.
## Microsoft login activation
Microsoft login can be activated as follows:
  * Define Nepton as an application in Azure. Instructions [here](<https://support.nepton.com/hc/en-gb/articles/360009872457>).
  * Configure Microsoft login in Nepton. Instructions [here](<https://support.nepton.com/hc/en-gb/articles/360010602957>).


## Google login activation
Instructions for Google login commissioning can be found [here](<https://support.nepton.com/hc/en-gb/articles/360016713117>).
## SAML SSO activation
Recommendation is to use SAML SSO only when the options mentioned above are not possible.
Instructions for SAML2-based SSO can be found [here](<https://support.nepton.com/hc/en-gb/articles/360002590097>).
